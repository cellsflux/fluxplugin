# Plugin stores: develop a plugin, publish it, install it

A **store** is any place plugins are listed and downloaded from. fluxplugin ships three kinds, and **GitHub is the default**:

| Store | You configure | How plugins get in | Best for |
|---|---|---|---|
| **GitHub topic** *(default)* | nothing | `fluxplugin publish` creates a release in *your own* repo; the repo topic `fluxplugin-plugin` makes it discoverable | open ecosystem, no approval needed |
| **GitHub catalog** | `{ "type": "github", "repo": "acme/plugin-store" }` | pull requests to a repo containing `index.json` | curated / reviewed store |
| **HTTP** | `{ "type": "http", "url": "https://plugins.acme.com/" }` | `fluxplugin store add` + upload the folder | company store, GitHub Pages, S3, CDN |
| **Local** | `{ "type": "local", "path": "./store" }` | copy folders | offline / shared drive |

Stores are listed in **`fluxplugin.config.json`** (`"stores"`). The same list is used by your **app** (*Plugins → Available*) and by the **CLI**
(`fluxplugin search`, `fluxplugin install`). You can have several stores at once.

---

## A. Develop a plugin (5 minutes)

```bash
# inside your app, or anywhere
npx fluxplugin plugin new weather -t backend         # basic | dashboard | backend   (add --tailwindcss if you like)
cd plugins/weather
npx fluxplugin dev                                    # rebuilds on save; the running app reloads the plugin
```
1. **Code** in `src/main.ts` (Electron side: IPC, services) and `src/renderer.tsx` (React: pages, widgets, menus). Learn the API in
   [PLUGIN-AUTHORS](PLUGIN-AUTHORS.md); what the host offers is in [CUSTOMIZING](CUSTOMIZING.md).
2. **Describe it** — this is your store page (*Plugins → Details*). Edit `plugin.json` and `README.md`:
   ```jsonc
   {
     "id": "com.acme.weather",            // unique, lowercase, never changes
     "name": "Weather", "version": "1.0.0",
     "description": "Forecast widget for your dashboard.",
     "author": "Acme", "license": "MIT",
     "repository": "https://github.com/acme/weather-plugin",   // ← where `publish` will release it
     "icon": "./assets/icon.svg",
     "screenshots": ["./assets/shot-1.png"],
     "video": "https://www.youtube.com/watch?v=YOUR_ID",
     "categories": ["Productivity"], "keywords": ["weather"],
     "permissions": ["ipc", "routes", "menus", "ui"],           // declare exactly what you use
     "engines": { "fluxplugin": "^1.0.0" }
   }
   ```
   `README.md` is rendered as the long description (headings, lists, tables, code, links; no raw HTML).
3. **Check it**: `npx fluxplugin validate .` — then try it in your app. Remove dev leftovers; users only ever get `plugin.json`, `dist/`,
   `assets/`, `README.md`, `LICENSE` — **never your TypeScript, `src/`, or `.map` files** (sourcemaps are only generated by `dev`).
4. **Version it** with semver (`1.0.0` → `1.0.1` fix, `1.1.0` feature, `2.0.0` breaking). A published version can't be replaced.

## B. Publish to the default store (GitHub)

**Once**: create a *public* GitHub repository for the plugin (`github.com/acme/weather-plugin`), push your code, and create a token:
GitHub → Settings → Developer settings → *Personal access tokens* → fine-grained, this repository, permissions **Contents: Read & write** and
**Administration: Read & write** (needed only to add the topic). Export it:
```bash
export GITHUB_TOKEN=github_pat_xxx        # PowerShell:  $env:GITHUB_TOKEN="github_pat_xxx"
```
**Every release**:
```bash
npx fluxplugin publish --dry-run          # builds + packages, shows what would happen, touches nothing
npx fluxplugin publish                    # does it
```
What `publish` does: builds the plugin (no sourcemaps) → creates `com.acme.weather-1.0.0.tgz` and `com.acme.weather-1.0.0.fluxplugin.json`
(name, version, permissions, **sha256**) → creates the GitHub release `v1.0.0` → uploads both files → adds the topic `fluxplugin-plugin`.
It refuses if the version already exists ("bump `version`"), the repo isn't reachable, or `description` / `icon` / `license` are missing.
Add `--sign-key my.private.key` to sign the package (`npx fluxplugin keygen` creates the pair).

New topics can take a few minutes to appear in GitHub search. Check with `npx fluxplugin search weather`.

**Update**: change code → bump `version` → `npx fluxplugin publish`. Apps see it in *Plugins → Updates*; the previous version is kept for **rollback**.
**Unpublish**: delete the release on GitHub (or remove the topic to hide the whole repository).

**Automate with GitHub Actions** (publish when you push a tag):
```yaml
# .github/workflows/release.yml
on: { push: { tags: ["v*"] } }
permissions: { contents: write }
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci
      - run: npx fluxplugin publish
        env: { GITHUB_TOKEN: "${{ secrets.GITHUB_TOKEN }}" }
```
(The built-in token can create releases but not edit topics; add the topic `fluxplugin-plugin` once in the repo settings.)

## C. Install from the store

* **In an app**: *Plugins → Available* lists plugins with their permissions; **Install**. Enabled automatically (or after the user approves permissions when your app uses `requireApproval`).
* **CLI**: `npx fluxplugin search weather` · `npx fluxplugin install com.acme.weather` (or `@1.0.0`) · `npx fluxplugin install ./file.tgz`.
* **Anonymous GitHub search is limited (60 requests/hour).** Set `GITHUB_TOKEN` (any token, no scopes) in the environment of the app or CLI to raise it.
  The app caches results for a minute.

## D. Run your own store

```bash
npx fluxplugin store init my-store                                   # creates my-store/index.json
npx fluxplugin package ./weather --out .                             # → com.acme.weather-1.0.0.tgz
npx fluxplugin store add com.acme.weather-1.0.0.tgz --dir my-store --base-url https://plugins.acme.com/
```
Upload the `my-store/` folder anywhere that serves static files, then add it to your app (and keep or drop the GitHub one):
```jsonc
// fluxplugin.config.json
"stores": [
  { "type": "http", "url": "https://plugins.acme.com/" },
  { "type": "github", "topic": "fluxplugin-plugin" }
]
```
* **Curated GitHub store**: put the same `my-store/` content in a repo `acme/plugin-store`, use `{ "type": "github", "repo": "acme/plugin-store" }`,
  and review plugin submissions as pull requests that edit `index.json`.
* **Code**: `new MainFramework({ stores: [...] })` or `registries: [new MyRegistry()]` — implement `PluginRegistry { name; search(query); fetch(entry, destDir) }` to talk to anything (npm, S3, your API).
* Format of `index.json`: `{ "plugins": [{ "id", "name", "version", "description", "permissions", "url", "sha256" }] }` — `url` may be relative.

## E. What protects your users

* Downloads must be **https** (loopback http is allowed for local testing) and match the published **sha256**; entries without a checksum are refused.
* Archives are extracted with path-traversal protection, size-limited (100 MB), and **sources, TypeScript, `.map` files and `node_modules` are deleted on install** even if a package contains them.
* Permissions are shown **before** install; with `requireApproval: true` nothing runs until the user approves; they can revoke later.
* Optional: `trustedKeys` + `requireSignature: true` in your `MainFramework` to accept only plugins signed by keys you trust.
* Plugin `main` code is **not sandboxed** — a store is a trust decision. Use a curated store or signatures for untrusted ecosystems ([SECURITY](SECURITY.md)).
* Limits today: public GitHub repositories only (private-repo downloads aren't supported yet).
